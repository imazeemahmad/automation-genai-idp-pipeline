## step_functions

This module deploys a step_functions compliant with organisation standards.

## Note about step functions code

To configure the Cloudwatch service to store the logs generated by the step functions code, it is necessary to create a role with the proper policy associated first for the 'role_arn' variable and the CloudWatch log group to use the arn in the 'logging_configuration_log_destination' variable. Please, check the following link for more information: https://docs.aws.amazon.com/step-functions/latest/dg/cw-logs.html

To define the step functions workflow, use the recommendations explained in the following link:
https://docs.aws.amazon.com/step-functions/latest/dg/concepts-amazon-states-language.html

## Dependencies

The step functions module has the following dependencies:
- IAM role
- Cloudwatch Log Group

## Usage

### Basic usage (plain JSON file)

```tf
module "step_functions" {
  source  = "registry.example.com/terraform-modules__aws-services/step_functions_state_machine/aws"
  version = "2026.4.3-weekly"

  name       = "snf-shared-modules-test-step-functions"
  role_arn   = "arn:aws:iam::123456789012:role/App_step_functions_cloudwatch_logs"
  definition = "src/step_functions/definition/definition.json"

  logging_configuration_log_destination        = "arn:aws:logs:eu-west-1:123456789012:log-group:/aws/step_functions/snf-step-functions-logs:*"
  logging_configuration_include_execution_data = true
  logging_configuration_level                  = "ALL"

  tags = {
    CE_Application_ID   = "APM2467135"
    CE_Application_Name = "Test application"
    CE_Environment      = "DEV"
  }
}
```

### With template variables

When you need to inject dynamic values (e.g. Lambda ARNs, table names) into your state machine definition, use a `.json.tpl` template file with `definition_variables`:

**`definition_with_vars.json.tpl`:**

```json
{
  "Comment": "A Hello World example that invokes a Lambda function",
  "StartAt": "InvokeLambda",
  "States": {
    "InvokeLambda": {
      "Type": "Task",
      "Resource": "${lambda_arn}",
      "InputPath": "$.input",
      "ResultPath": "$.result",
      "End": true
    }
  }
}
```

**Module invocation:**

```tf
module "step_functions" {
  source  = "registry.example.com/terraform-modules__aws-services/step_functions_state_machine/aws"
  version = "2026.4.3-weekly"

  name       = "snf-shared-modules-test-step-functions"
  role_arn   = "arn:aws:iam::123456789012:role/App_step_functions_cloudwatch_logs"
  definition = "src/step_functions/definition/definition_with_vars.json.tpl"

  definition_variables = {
    lambda_arn = aws_lambda_function.hello.arn
  }

  logging_configuration_log_destination        = "arn:aws:logs:eu-west-1:123456789012:log-group:/aws/step_functions/snf-step-functions-logs:*"
  logging_configuration_include_execution_data = true
  logging_configuration_level                  = "ALL"

  tags = {
    CE_Application_ID   = "APM2467135"
    CE_Application_Name = "Test application"
    CE_Environment      = "DEV"
  }
}
```

> **Note:** JSONPath expressions like `$.input` and `$.result` are safe to use alongside `templatefile()` variables. Terraform's template syntax only interpolates `${...}` sequences, so `$.` prefixed expressions pass through unchanged.

## Inputs

| Name | Description | Type | Default | Required |
|------|-------------|------|---------|:--------:|
| definition | (Required) Path to a JSON file that contains the Amazon States Language definition of the state machine. When `definition_variables` is provided, the file is processed with `templatefile()`; otherwise it is read with `file()`. | `string` | n/a | yes |
| name | (Required) Name of the Step Functions | `string` | n/a | yes |
| role\_arn | (Required) The ARN of the IAM role to use for this state machine | `string` | n/a | yes |
| tags | A map of tags to assign to the resource. Must include CE\_Application\_ID, CE\_Application\_Name, and CE\_Environment. | `map(string)` | n/a | yes |
| definition\_variables | A map of variables to substitute in the definition file using templatefile(). When provided, the definition file is processed as a template. When empty (default), the file is read as-is. | `map(string)` | `{}` | no |
| logging\_configuration\_include\_execution\_data | (Optional) Set to true to include the execution data in the log. | `bool` | `false` | no |
| logging\_configuration\_level | (Optional) Set the logging level. | `string` | `"OFF"` | no |
| logging\_configuration\_log\_destination | (Optional) The ARN of the CloudWatch Logs log group to which you want to send log data. | `string` | `"*"` | no |

## Outputs

| Name | Description |
|------|-------------|
| step\_functions\_arn | Step functions ARN |
| step\_functions\_name | Step functions name |
